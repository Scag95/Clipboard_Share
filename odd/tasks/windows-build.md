# Windows build (untested) for the Nudge 0.1.0 pre-release
Make the Nudge server and CLI runnable on Windows 10/11 x64 and ship a downloadable build in the same GitHub pre-release as the Arch package and the Android APK. It cannot be tested here (no Windows device), so everything must be reasoned from the code and compiled with GOOS=windows. Branch: feat/windows-build. Base: a3051e7.

## Specs
- S1: The user asked: "haz el merge, compila para windows sin comprobar, ya lo hgao yo, ahora mismo no tengo un dispositivo windows. quiero subirlo también al repo con un prerelease. arregala todo lo que necesites para que se pueda ejecutar en windows aunque no puedas probar." — ship a Windows build in the pre-release and fix whatever is needed for it to run on Windows, even though it cannot be tested here; the user will test it.
- S2: Two executables are built from the same source (`./cmd/server`), CGO disabled: `nudge.exe` (console subsystem: the `nudge pair ...` CLI and, if run by hand, the server with log output on the console) and `nudge-background.exe` (built with `-ldflags=-H=windowsgui`, no console window: the same program, used for the login autostart). Both default to server mode with no arguments, exactly as the Linux binary.
- S3: Config directory on Windows is `%APPDATA%\nudge` (os.UserConfigDir), holding state.json, the control socket and the log. Linux keeps `~/.config/nudge` and the legacy fallback/migration exactly as today (the legacy `clipboard-share` migration only applies on Linux). Env overrides `NUDGE_*` keep working. No Unix-only assumption (hard-coded `.config`, `0700/0600` semantics, `/` separators) may break on Windows; `os.Chmod` modes are ignored there.
- S4: Pairing on Windows (there is no Qt panel): when a phone requests pairing, the background server shows a native Yes/No message box (user32 MessageBoxW through golang.org/x/sys/windows or syscall, no cgo) with the phone's name and IP, text sanitized and truncated because it comes from the LAN; the default button is No (so a stray Enter or space denies); no topmost/foreground flags; one dialog at a time with a queue and a cap, expired requests are skipped. Yes calls the broker's Approve(id), No/close calls Deny(id). `nudge pair list|--last|...` keeps working from the console as an alternative. Linux behavior (notify-send, the Qt panel) is unchanged.
- S5: With no console (nudge-background.exe) logs go to `%APPDATA%\nudge\nudge.log` (append, with a size cap or rotation to avoid unbounded growth) instead of a missing stderr; the console build keeps logging to stderr.
- S6: The control socket on Windows keeps using AF_UNIX (supported on Windows 10 1803+): handle stale socket removal, path length and the chmod call without failing the server when chmod is a no-op; if listening fails, log it and keep the HTTP server running (pairing by dialog still works because it calls the broker in process).
- S7: Review internal/clipboard/clipboard_windows.go and internal/input/sender_windows.go for 64-bit and runtime bugs (SendInput struct size and alignment on amd64, key mapping, error handling) and fix what is clearly wrong; keep the shared validation and limits identical to Linux.
- S8: Packaging (no Windows tools available here, so no NSIS/Inno): a build script `scripts/build-windows.sh` that cross-compiles both executables (CGO_ENABLED=0 GOOS=windows GOARCH=amd64, -trimpath, -ldflags "-s -w"), generates `nudge.ico` from `pkgbuild/nudge.svg` (rsvg-convert and ImageMagick are available), and produces `dist/nudge-<version>-windows-x64.zip` plus its SHA256. The zip holds `nudge.exe`, `nudge-background.exe`, `nudge.ico`, `Install Nudge.cmd` (double-click launcher that runs install.ps1 with ExecutionPolicy Bypass), `install.ps1`, `uninstall.ps1`, `README-windows.txt`.
- S9: `install.ps1` installs per user (no admin needed) to `%LOCALAPPDATA%\Programs\Nudge`, creates a Start Menu shortcut, offers an autostart shortcut in the user's Startup folder that runs `nudge-background.exe` (on by default, `-NoAutostart` skips it), adds the install dir to the user PATH so `nudge pair` works, starts the server, and offers to add the Windows Firewall inbound rule for TCP 8765 (private networks) via an elevated `netsh` step, explaining what it does and degrading gracefully if declined. `uninstall.ps1` removes shortcuts, the PATH entry, the firewall rule (if present), stops the process and the install dir, and asks before deleting `%APPDATA%\nudge`. A second script `toggle-autostart.ps1 on|off` (also a Start Menu shortcut) enables or disables only the autostart so the user can decide, like the Linux switches.
- S10: Docs: a Windows section in README.md (what it is, that it is untested, how to install, pair with the dialog or the CLI, autostart switch, firewall, uninstall, where the log is, known limits: no tray panel on Windows yet, unsigned executables trigger SmartScreen).
- S11: Existing behavior preserved: `go build ./... && go vet ./... && go test ./...` pass on Linux, `GOOS=windows go build ./... && GOOS=windows go vet ./...` pass, and Windows-only logic that can be unit tested on Linux (config root selection, dialog text sanitizing, queue/cap logic, log rotation) has tests behind a testable seam.
